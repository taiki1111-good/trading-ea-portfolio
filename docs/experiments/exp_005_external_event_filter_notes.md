# exp_005_external_event_filter_notes

## 仮説
外部イベント/API を使って売買方向判断を行うのではなく、危険局面の補助判定・停止閾値補正・イベント検知に限定することで、ルールベース中核を維持しつつ安全性を高められると仮定する。

## 想定データ源カテゴリ
- 経済指標カレンダーAPI
- 中央銀行や公式機関のRSS/公式配信
- リアルタイム金融ニュース配信
- 企業決算/提出書類系の公式データ
- SNS/X系（補助候補、ノイズと再現性の問題があるため優先度低め）

## 用途の方針
- 方向判断には使わない
- 危険局面検知に限定する
- 具体的には以下を狙う
  - 指標前後の停止判定
  - 公式発表の直前・直後の停止閾値補正
  - 速報ニュースによるリスク回避タイミングの検出
  - 公式データの重大度評価によるフィルター強化

## 評価指標
- 外部イベント入力がある場合の停止条件比較テスト結果
- 誤停止率
- 危険局面回避率
- フィルターによる見送り回数と実際の損失回避効果
- 外部イベント判定の信頼性と一貫性

## 誤停止と回避効果の比較
- 外部イベント入力なし/ありでの停止条件成立差
- 誤停止が許容範囲内かどうか
- 危険局面をどれだけ早く回避できたか
- 実際の損失回避効果

## 将来の実装上の注意
- 外部イベント入力は本体ロジックに直接影響させず、RiskFilter や EventFilter の補助情報として扱う
- SNS/X 系は補助候補とし、ノイズや再現性問題を評価して優先度を低めに扱う
- 外部ソースの信頼度・重大度を明示的に管理する変数を用意する
- 外部入力の遅延・欠損・誤検知に備えたフェールセーフを設計する
- 方向判断を拡張したい場合でも、まずは停止/見送り・閾値補正としての有効性を確認する
